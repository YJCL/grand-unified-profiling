# Orba product guidance

Read DESIGN.md for the current UI and writing direction. User instructions override older marketing plans.

- Main screens and product prose should serve the user's purpose. Do not add unnecessary AI-production promotion, calculation/audit/version details, implementation notes, or constant retired-feature/operations notices. Retain calculation metadata internally.
- Remove retired feature cards and primary navigation naturally; preserve stored history and authenticated access in secondary account settings.
- Use brief, concrete, contextual guidance only for uncertainty that affects the user. Do not keep obsolete warnings after input has been corrected.
- Keep legally/contractually required and safety/misrepresentation-prevention explanations in appropriate terms/help pages and minimal input cautions. Never claim human authorship falsely.
- This is a product/style principle, not a change to approval rules. Preserve closed new reception/chat APIs, ownership checks/RLS, historical data, calculation metadata, and existing non-chat functions.
