# Orba UI and Japanese birthplace correction

The main reading previously displayed a large calculation/version/audit notice before the interpretation, including stale birthplace uncertainty from stored snapshots. The dashboard also retained retired chat notices, chat primary navigation, and an operations banner above the mobile navigation. These interrupted the retained reading and I Ching experience.

The dashboard now presents its reading directly. The extended daily reading opens from the daily card. I Ching has a dedicated card and navigation item; old stored `chat` widget-order identifiers map to it locally without rewriting records. Saved conversations are still owner-authenticated and read-only, reachable through secondary account settings. Subscription management/cancellation is also preserved there. The permanent membership/operations banner and retired-chat notice are removed. Calculation versions and assumptions stay in stored/server metadata; snapshots are not recalculated or overwritten. Minimal input privacy cautions and the `/safety` disclosure remain. No claim of human authorship is introduced.

Japanese lookup previously depended on a short major-city alias list in an English-only city dataset. Kesennuma was absent, causing a Tokyo fallback with unknown-place/timezone metadata. A pinned static public municipality dataset now supplies domestic name matching and approximate municipality coordinates. Country/prefecture-only and repeated Japanese place names can establish the timezone without inventing coordinates. Country-qualified foreign cities retain their own timezone; unresolved nonempty/ambiguous foreign places require correction rather than silently using JST. Empty place remains internally provisional. Newly computed facts receive `2026-10-03-v3`; old metadata remains unchanged. Coordinate precision is limited as described in `data/geo/README.md` and optional source details.

The product-language principle is recorded in tracked `AGENTS.md` and `DESIGN.md`, and appended to the existing local Orba `AGENTS.override.md`. It concerns product/style choices, not approval rules. Closed new registration, profile creation, new billing and chat mutation APIs, ownership/RLS, stored history and non-chat functionality remain protected. No production database or real account was changed during verification.

Validation: 182 offline engine/safety/security/lint-boundary tests; TypeScript, lint and build; hidden headless desktop/mobile reading, profile correction, I Ching, calendar, secondary history and contract-management screens. Browser APIs are intercepted with fictional fixtures, including stale calculation metadata and a legacy widget order. No real user data, model request, payment, or production API write is used. See `docs/audit/natural-ux-ui-verification.json` for the local screen checks. Production assets will receive the same hidden screen checks after the approved CI/merge/deployment.
