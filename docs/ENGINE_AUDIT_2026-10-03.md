# Orbaは計算バグを修正し、旧鑑定を残したうえで提供方式を見直す

日柱の2日ずれと、易の64卦中48卦を取り違える不具合をローカルで修正した。修正後は、日柱800件が二つの独立した暦実装と一致し、易64卦が古典本文と一致した。計算の土台は再利用できる。ただし、計算から作る性格・運勢の説明には、別の確認が必要である。利用時のAI APIをなくす特典は、端末内の計算と、編集済みの固定解説で構成できる。

調査日：2026年10月3日。対象は `https://orba.life` と `YJCL/grand-unified-profiling`。開発元は `F:\AI-Projects\Orba\Grand_Unified_Profiling`、今回の修正は作業フォルダー内の隔離コピー `orba-release`、ブランチ `fix/engine-validation-20261003` にある。基点は公開済みの `f7ce8789cdafbb810b01cc30571f2b11cbbb95fa`。計算変更のpush・deployは行っていない。Fドライブの既存作業差分も維持している。

実ユーザーの出生情報・相談文・鑑定履歴は読み取っていない。検証は架空の日付、公開された暦・天体暦、DBの権限メタデータだけを使用した。モデルAPI、課金、アカウント作成、GUI操作は使っていない。実際の侵害の有無は今回の監査では確認していない。

## 独立検証が支える範囲と採用した暦規約

日柱の800件は、1900〜2099年の各年1月1日・3月1日・6月15日・12月31日の現地12:00、JSTで比較した。二つの参照実装間の不一致は0件。修正前のOrbaは800件すべてが2日先、修正後は800件すべて一致した。全日付を総当たりした数字ではない。1900年の非うるう年、2000年のうるう年、1986-05-29、2000-01-07、2000-12-25、2024-02-29の追加例も一致した。

一つ目は、Edward M. Reingoldによる[GNU Emacsのcal-china.el](https://raw.githubusercontent.com/emacs-mirror/emacs/7586a71d7c465e3a403dd6f04b76cac38a995189/lisp/calendar/cal-china.el)。西暦1年1月1日を1とする通日Rata Dieに対し、1始まりの干支番号で通日+15を使う。OrbaのJDN関数を流用せず、JavaScriptのUTC通日から参照値を作った。二つ目は、作者6tailの[lunar-javascript](https://github.com/6tail/lunar-javascript)の[固定配布版1.7.7](https://registry.npmjs.org/lunar-javascript/-/lunar-javascript-1.7.7.tgz)。配布アーカイブのSHA-512と、実際に使ったlunar.jsのバイト一致を確認した。npmのgitHeadにあるlunar.jsは配布版と異なるため、再現時は上記アーカイブを使う。

採用規約は先発グレゴリオ暦、出生地の民用日付、日柱の日替わりは現地00:00である。日柱と時柱の計算では地方真太陽時・均時差の補正をしない。2024-02-29の22:59・23:00・23:59と3月1日の00:00も比較した。参照ライブラリのsect1は23時に日柱を翌日へ切り替え、sect2は日柱を00時で切り替えるが、23時台の時柱天干は翌日基準を使う。Orbaは従来どおり、その民用日の日干から時柱を求める。23時台の時柱は両sectと一致しないため、今回の修正を「全流派の四柱推命に一致」とは表示できない。800件の正午における2日差は、この流派差で説明できない。

年柱・月柱は太陽黄経による節入りで、年は黄経315度の立春、月は315度から30度ごとの節を境界にする。一般的な春節区切りの生肖との違いを表示する必要がある。2024年2月7日はOrbaでは甲辰・龍だが、春節区切りではまだ前年となる。[香港天文台の2024年暦](https://www.hko.gov.hk/en/gts/time/calendar/pdf/files/2024e.pdf)も、立春2月4日、春節2月10日を区別している。今回は「ChineseZodiac」の方式や名称を変更していない。

易は、下から上へ6本の爻を並べる三枚コイン法を採用する。各爻6・7・8・9の確率は1/8・3/8・3/8・1/8で、6と9が変爻になる。[Kanseki Repositoryの周易・固定コミット](https://github.com/kanripo/KR1a0001/tree/8284adbf9e3435d713180e24f05bf75f8b7d1d96)の64ファイルから、初爻〜上爻の「九／六」見出しを抽出して識別を照合した。例えば[姤の本文](https://raw.githubusercontent.com/kanripo/KR1a0001/8284adbf9e3435d713180e24f05bf75f8b7d1d96/KR1a0001_044.txt)は初爻が陰、残りが陽となる。修正前48件不一致、修正後0件。検証対象は卦の識別であり、吉凶や行動助言の的中ではない。

天体位置は、NASA/JPL Horizonsの地心観測者500@399、日付の黄道座標、見かけの黄経（quantity31）を使った。日時は2000-01-01 12:00 UTCと2024-02-04 08:27 UTC、対象は太陽・月・水星・火星の計8件。最大差は水星の3.085秒角で、5秒角以内の回帰検証が成功した。各リクエストの全パラメータと参照URLは `scripts/fixtures/ephemeris-jpl.json` にある。[NASA/JPL Horizons APIの仕様](https://ssd-api.jpl.nasa.gov/doc/horizons.html)から再取得できる。他の天体、全時代、ASC・MCの式、ヒューマンデザイン全体を認証した結果ではない。

DSTではニューヨークの2024-03-10 02:30（非存在）と2024-11-03 01:30（重複）、サモアの2011-12-30（欠落日）を検証した。解決は実行環境のICUの履歴に依存する。同名都市の選択や都市データの精度は別の課題である。入力画面には、重複時刻の選択肢と不明項目の説明を追加する必要がある。

## 計算値・古典解釈・AI作文・予測の妥当性を分ける

| 層 | 確認した事実 | 提供時の扱い |
|---|---|---|
| 計算 | 日付・時刻から決定的な数値を作る。日柱と卦の識別は上記の参照検証を追加 | 規約と版を表示し、入力不明時の推定を明示 |
| 古典・体系の解釈 | 八卦の本文、数秘の還元規則などを、現在の解説に結び付ける部分は編集判断 | 古典上の意味、Orba独自の要約、現代的な提案を区別 |
| AI作文 | `/api/divine`は計算結果を渡して文章を作る。「現在の運気」を要求するが、同ルートは今日のトランジット計算を渡していない。色・数字・戦略もAIが選ぶ | 旧AI文章を自動的に新版の計算解説として転用しない。特典では固定文を編集して使う |
| 科学的予測 | このリポジトリでは、出生情報から性格や将来を予測する精度の検証資料を確認できなかった | 的中率や統計的診断として売る根拠は、今回の計算監査からは得られない |

既存のAI安全フィルターは危険な文章を制御する目的であり、天体値との整合は検証しない。架空入力で太陽が山羊座となる計算結果に対し、モック文章「太陽は魚座1度です。」を渡したところ、安全フィルターは書き換えず返した。これは事実照合機構がないことの実演で、実際のモデルの誤答率を測ったものではない。監査中にモデルは呼んでいない。

数秘と修正版の日干支、参照検証済みの天体位置、修正版の易の卦は、娯楽・振り返り用の固定解説と組み合わせる候補になる。九星の月命星は独立した月別表との検証がまだない。ヒューマンデザインは平均交点と近似・フォールバックを含み、公式図との全体比較は未実施。宿曜は月のトロピカル黄経を27等分しており、「日本の宿曜方式」という表示を裏付ける暦規約と日付表を確認できていない。この3体系は初期特典から外す案を勧める。日次運勢スコアはトランジット70%・バイオリズム30%など独自の重みを使うため、成功確率や客観的な強み診断として扱わない。

## 旧鑑定は残し、再計算は本人の選択にする

ローカル修正では、新しく作るプロフィールと日次計算に `calculationVersion=2026-10-03-v2`、新しい易に `dataVersion=1.0/bottom-up-v2` を付けた。易の新規行の `profileVersion` は、従来のユーザーIDから実際の計算版へ変更した。既存行に版を書き足す処理や、保存済み鑑定を更新する処理は追加していない。

既存の易は保存済み番号・解釈・dataVersionを保持して再表示する。版情報のないDiagnosisは「旧版・計算版不明」として扱う案とする。frozenSignature／frozenCompassも残す。現在の再鑑定は、生成後にこの二つの旧保存値を上書き反映するため、新版を公開すると他の文章との混在が起こり得る。これを新版として一括表示しない設計が必要である。

再計算の案は、旧結果を見られるまま、「計算の修正内容」と「一部の結果が変わること」を示し、本人が選んだ場合だけ別の結果を作る方式である。同じ入力スナップショット、採用した暦規約、計算版、解説版、作成時刻、比較元の結果IDを、新しい結果に保存する。新しい保存先と旧い保存先は分け、既存行を更新しない。端末内だけの特典なら、この比較も端末内で行い、保存は本人が選ぶローカルファイルだけにできる。

この再計算導線、旧版表示、frozen項目の扱いはまだ実装していない。再計算を契機にAIを呼ぶ案も採用していない。公開前の確認事項は、00時区切り・23時台の時柱規約、旧版の表示、新版を別結果にする導線、DST入力、旧チャットの提供方針である。今回の差分を出しただけでは、既存データの整合性やサービス再開準備が完了したとは扱えない。

## PDF特典は入力を端末内に留める構成が可能

推奨案は、購入者にPDFと、端末で開ける計算ツールのZIPを渡す方式である。ツールは計算用JavaScriptと固定解説を同梱し、登録・ログイン・チャット・履歴サーバーを持たない。氏名と自由相談は入力項目から外し、必要な日付・時刻・都市だけをメモリ上で扱う。入力をlocalStorage、Cookie、URL、解析イベントへ記録しない。外部API、外部フォント、解析タグをなくし、通信を禁止する設定を加える。計算時のAI API実行費は0にできる。

最小構成は数秘・修正版の日干支と固定の振り返りシート。出生時刻や場所を扱う天体図を入れる場合は、不明・推定を分かるように表示する。[Astronomy Engineはブラウザー用JavaScriptも提供している](https://github.com/cosinekitty/astronomy#javascript)。易をブラウザーで使うにはNodeのcrypto依存を[Web Crypto](https://www.w3.org/TR/webcrypto/)へ置き換える作業が必要で、現コードをそのままZIPに入れて動く状態ではない。静的Web版も候補だが、配信事業者にはアクセス元IP等が届く。ZIPの端末内利用は、入力値を運営サーバーへ送らずに使える構成に適している。既存サイトの解析タグや共通レイアウトは流用せず、通信を含まない配布物として検証する。

PDF内のURLや共通パスワードによる購入者特典は共有を完全には防げない。個別の利用権チェックを厳しくすると、認証サーバーや購入データの運用が必要になる。入力情報を持たないことを優先するなら、共有可能性を受け入れる特典設計が簡潔である。PDF販売先には購入・決済情報の取り扱いや手数料が残るため、事業全体の費用・個人情報がゼロになるという説明はしない。販売先の選定や大規模な事業移行は未実施である。

## 公開済みのセキュリティ対策と、停止判断を分ける

orba.lifeは10月3日の再確認で `f7ce878…` のデプロイがREADYで、[PR14](https://github.com/YJCL/grand-unified-profiling/pull/14)のログ対策を含む。対象10テーブルはRLS有効、anon／authenticatedのテーブル権限なし。Cookieなしの架空IDによるUser・Chat取得は403。匿名の新規課金申込は503を返しており、新規課金導線は停止状態である。これらは現在の制御の確認であり、過去に情報が取得されたかを示す調査ではない。第三者解析の設定・過去ログ全体の監査や消去も今回の確認には含めていない。

有料提供を見合わせる連絡やKOMOJU申請の取り下げ希望は、サービス全体の停止を実行する操作とは別である。無料の登録・鑑定・チャット等は、今回停止していない。一時停止する場合は、画面だけでなく、User作成、登録、鑑定保存、divine、chat POST、daily GET、daily-reading POST、iching POSTをサーバー側で制御する。dailyはGETでもキャッシュ未作成時にモデルを呼ぶ。通知の停止にはpush/sendの定期実行も対象になる。

ログイン、問い合わせ、本人の閲覧・削除、取消の窓口をどう残すかは個別に決める。決済Webhookと状態整合処理を一律停止しない。現行のbilling/reconcileは新規課金を行わず、期限切れで失敗・解約等の状態にあるユーザーのisPremiumを更新する。既存の契約・自動更新の有無は実ユーザーデータを読んでいないため未確認で、アカウント閉鎖・一括解約・削除は行っていない。

## 再現用の成果物と公開判断

本ブランチでは46件の計算テスト、86件のAI安全テスト、24件の権限・プライバシーテスト、5件のlint依存互換テスト、計161件が成功した。型検査、lint、ビルドも成功。lintには既存の画面遷移警告2件が残る。ビルドではダミー環境値、外部通信遮断、ローカルのフォント応答を使用し、実際のDBやモデルへのアクセスを防いだ。このローカルビルド成果物は本番配布用ではない。

`npm run test:engine` はネットワーク不要で、保存済みの参照値を使って再現できる。参照値と出典は `scripts/fixtures/{iching-classical,ephemeris-jpl}.json`、詳細な前後比較は `docs/audit/` に保存した。GNUの式とOrbaのJDN式は別の実装である。第二の暦ライブラリとの比較は監査時に行い、本番依存関係には追加していない。

承認対象はこのローカル差分の公開範囲と、旧版をどう表示するかである。先に旧履歴の表示維持と版管理をレビューし、再計算・入力画面・サービス提供方針が決まってから公開する案を勧める。今回、計算変更の本番反映、既存鑑定の再計算、データ削除、旧サービスの全面停止、PDF事業への移行は実行していない。
